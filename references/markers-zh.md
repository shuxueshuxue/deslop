# 中文标记表

判据：**这句话是在陈述，还是在表演？**

「用词严谨平实」不是 AI 味，那是目标。AI 味是夸张、性感、自作聪明的类比与修辞。

---

## 语气基准，日本译制片

**AI 语气和译制片语气正好是两极。一个狡猾机灵，一个谦逊朴实。**

下面八类，每一类都是「机灵」的一种具体形态。生动的类比是机灵，对偶反转是机灵，
段末那句短促断言是机灵，挑一个更显学问的词也是机灵。它们都在做同一件事：
**向读者证明写的人很聪明。**

所以最省事的自检是问一句，不必逐条对表：

> 这句话是在**老实说事**，还是在**显得聪明**？

目标语域夹在书面与口语之间，两头都不是。一个好用的校准是**日本译制片的中文配音**：

- 完整句，不省主语，不用省略号式的断句
- 动词多为双音节（「阻断」而不是「拦」，「承载」而不是「装」）
- 不用俚语、网络词、圈内黑话
- 语气平稳，既不夸张也不亲昵；郑重，但不端着

**用法：改完把句子念出来。** 它能作为译制片台词说出口，语域就对了。
两头跑偏都会立刻听出来。太随便（「这玩意儿根本跑不起来」）或太文（「此机制之判据」）都是。

这条基准同时划掉了两类错误。把平实做成大白话，以及把严谨做成掉书袋。

## 1. 动作类比

把技术动作说成有画面感的日常动作。读起来生动，但它在演。

| 表演 | 陈述 |
|---|---|
| 接住每个事件 | 对每个事件创建一条记录 |
| 成本都塌了 | 成本大幅下降 |
| 把人叫回来 | 触发人工复核 |
| 当场拦下这次提交 | 拒绝这次提交 |
| 钉到某个函数 | 绑定到某个函数 |
| 误伤 | 误报 |
| 场景挂了 | 场景测量未通过 |
| 请盯两件事 | 请关注两点 |
| 一个 session 能饿死另一个 | 一个 session 会占满配额，导致其他 session 无法分配 |

## 2. 拟人

让机制、历史、文档、成本、状态这类抽象主语做人或生物的动作。

| 表演 | 陈述 |
|---|---|
| 状态活不过一次调用 | 调用结束后状态失效 |
| 历史永远不会提醒你 | 历史记录无法指示当前状态是否一致 |
| 这个 session 就一直活着 | 该 session 保持存活 |
| 会话级 harness 缺的是寿命 | 会话级 harness 的状态不能跨会话保留 |
| 前几代都是这么死的 | 前几代都因此被弃用 |
| 只活在那一次对话里 | 只保存在那一次对话中 |
| 测试不会说谎 | 测试的结果可复现 |

## 3. 对偶反转

`不是 X，是 Y` · `A 不在 B，在 C` · `前者…后者…`。
英文社区把这一条列为最可靠的 LLM 指纹，中文同样成立。

| 表演 | 陈述 |
|---|---|
| 判的是「该不该回头看」，不是「对不对」 | 判断是否需要复核，不判断代码正确与否 |
| 短板不在能力，在寿命 | 局限是状态不能跨会话保留 |
| 让它们跟着仓库走，不跟着工具走 | 这些配置存放在仓库中 |

一次是金句，两次是风格，七次是套路。**数出总数**，超过两三次就该砍。

## 4. 戏剧性收尾

段落末尾抛一句短促断言制造回味。功能是让读者「回味」，不是传递信息。

| 表演 | 陈述 |
|---|---|
| 这部分代码里找不回来。 | 这部分信息无法从代码恢复。 |
| 剩下的问题只有一个，它还是会漂。 | 但仍有一个问题：两者之间照样会出现偏差。 |
| 都不需要读它们的代码。 | 两项判断都不需要阅读代码。 |
| 而它们自己也分不清哪些改动带着风险。 | agent 也无法标示哪些改动风险较高。 |

识别法：把这句删掉，信息有没有少？没有就是装饰。

## 5. 强调副词与自我评价

**副词**：真正、本质上、恰恰、正是、唯一、必然、显然、彻底、从不、永远。

**自我评价**：老实说、诚实地讲、说得对、值得一提、更重要的是、关键在于、核心是。

| 表演 | 陈述 |
|---|---|
| Naur 说得对，理论无法从文档重建 | 与 Naur 的结论一致：理论无法从文档重建 |
| 关键在于 session 是所有者 | session 是该次评审的所有者 |
| 这恰恰是最该说清楚的一点 | （删掉，直接说那一点） |

「说得对」是**作者在给引文打分**，不是陈述。

## 6. 破折号插入语

`——` 用来插入补充说明。LLM 极度偏好它。**数出总数**。
更要注意分布：如果多数破折号都落在段落收尾处，那是模板，不是行文。

改法：拆成两句，或换成冒号、括号、逗号。

## 7. 抬高的书面词

明明有常用词，却挑了一个更书面、更生僻、听起来更「专业」的。
LLM 尤其爱这么干，它在挑显得有学问的词。读者的感受是**这人在端着**。

| 端着 | 常用 |
|---|---|
| 判据 | 判别方法 · 判断依据 |
| 受治文件 | 被管着的文件 |
| 驻留 | 留在内存里 |
| 沉淀 | 留下来 · 存到哪 |
| 涵盖 | 包括 |
| 旨在 | 用来 |
| 藉由 / 故而 / 遂 | 通过 / 所以 |

`判据` 要报候选，而不是直接改成口语。真实审稿里「drift 判据」被判为 AI 味，改成了
「drift 检查的判别方法」；但改成「drift 怎么判」同样是过度更正。

**边界一：平实不等于口语。** 中文书面语默认双音节动词，把词改成单字反而掉出书面语域。
`承载` 不该换成 `装`，`阻断` 不该换成 `拦`，`复核` 不该换成 `再看一遍`。
要换掉的是**生僻**，不是**书面**。判断标准是这个词常不常用，不是它有几个字。

**边界二：改完念一遍。** 若读起来像在跟人聊天而不是在写文档，就是改过头了。

三种邻近毛病一并查：

- **文白夹杂**：口语句子里混进文言虚词（其、之、乃、故、遂、藉）。
- **动词名词化**：`进行/实现/完成 + 名词`。「进行判定」→「判」，「实现隔离」→「隔开」。
- **四字格堆砌**：为整齐凑的四字短语（同生共死、逐条落地、一以贯之）。

注意与「不要误伤」一节的边界。**领域标准名称不算端着**。drift、anchor、worktree、
precision/recall 是术语，平俗化它们只会让文本显得外行。

## 8. 词汇复读与圈内黑话

**复读**：LLM 会咬住一个生动词反复用。同一个比喻在全文出现三次以上就该换掉两次。
统计「活/漂/钉/塌/死」这类比喻族的总频次。

**黑话**：赛道、闭环、抓手、对齐、颗粒度、心智模型、第一性原理、护城河。
学术与技术场合直接换成本义。

| 表演 | 陈述 |
|---|---|
| 同赛道都在把记录做细 | 相关工作都在提高记录粒度 |
| 测试也绿 | 测试通过 |
| 踩过的坑 | 已知的失败案例 |
| 打通了整个链路 | （说清楚具体连接了哪两个环节） |

## 9. 结构节奏

词都平实，结构仍可能暴露模型。常见形状是每段先铺垫、再转折、最后抛一句总结；连续句子长度
相近；每项都凑成三件。读者会先听出这个节拍，再注意到具体词。

| 表演 | 陈述 |
|---|---|
| 活动包括演讲、讨论和社交机会。 | 活动包括演讲和讨论，间隙可以自由交流。 |
| 先说背景、再讲方法、最后展望未来。 | 先交代背景，再说明方法。未来安排见项目计划。 |
| 这说明问题已经解决。 | （若无新信息，删掉；否则写出解决了什么。） |

三项并列不是禁用规则。保留它需要有真实的三项；只是为了显得完整而凑三项，就改成两项或写成
真正的列表。读完全文，再检查段落长度和收尾是否都长成同一个模子。

## 10. 套话式归因与结尾

`专家认为`、`观察者指出`、`行业报告显示`如果没有具体人名、报告或可核对的事实，只是在借一个
不存在的权威给句子加重量。给出来源；给不出就直接说自己的判断，或删掉归因。

`尽管存在一些挑战，未来前景依然光明`、`未来展望`这类句子没有说明挑战是什么、下一步做什么，
也没有传递结果。改成具体计划、日期、数字，或者删除整句。不要用乐观情绪替代论证。

## 不要误伤

术语看着生动，但它是标准名称时，**不许改**。

- 机制就叫 *drift*（漂移）→ 「spec 漂移」是术语，不是比喻
- *anchor*（锚点）、*warm cache*（热缓存）、*garbage collection*（垃圾回收）、*starvation*（饥饿）

判断法：专业读者会不会认为这是这个东西的标准叫法？会，就留着，把周围的话改平。
改错了比留一个标记更糟，它会让文本读起来像外行写的。
