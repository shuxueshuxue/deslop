# docs

`pipeline.html` 是这套流程的图解，一页一张图。

图是纵向的九个步骤，左边一列是步骤号，方块里标出这一步由谁执行。三种颜色分别是机器跑，人读，脚本测量，
另加一种表示冻结不许改。这个区分有用，因为整条流程里只有一步必须由人做，
而且必须换一个没写过这篇文本的人。

图下面接三节：

- **步骤**，每步进什么，做什么，出什么，哪个上游项目贡献的
- **指标分层**，GATED / CAPPED / REPORTED，外加被降级的三条
- **实跑读数**，论文框架稿那一批的前后数字

浏览器直接打开。**没有任何外部依赖**，图是手写 SVG，不加载脚本库，整页 30 KB。
深浅色跟随系统，右上角可手动切。

## 两次重写

**第一次**把"类似流水线"读成了"写一整套工厂比喻"。工位，夹具，遮蔽胶带，通止规，流转卡，返工线，
还专门写了一段论证"为什么比喻是准的"。指标全绿，四遍回读全过，读者一眼看出是 AI 味。
删掉了约 120 处比喻词，保留线性分段的版式，因为那才是"流水线"在这里的意思。
这条规则升到了原则层，写在 `../references/taxonomy.md` 的 H6。不造比喻，没有场景豁免，也没有阈值。
它不进计数集。名字，死隐喻，字面用法，活比喻，这四样在词面上无法区分，脚本看见的一律只是候选。

**第二次**去掉了 mermaid，图改成纵向。顺带删掉了 vendored 的 3.5 MB 运行时，
整页从 3.6 MB 降到 30 KB，也不再需要在浏览器里执行一次布局算法才能看见图。
