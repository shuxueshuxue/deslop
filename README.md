deslop 是一个 Claude Code skill。给它一段中文或英文文本，它先量一遍，逐行审计，改写，再量一遍，
交出前后两组可以核对的数字。它改文本的说法，不改文本的主张。

## 它在找什么

模型写出来的句子有固定的毛病，可以逐条列出，也可以数。它们分成两类，卖的东西不一样。

**第一类，证明写的人很聪明。**生动的类比，对偶反转，段末那句短促断言，挑一个更显学问的词。
判断标准只有一句：

> 这句话是在**说事**，还是在**显得聪明**？

**第二类，证明写的人是圈内人。**黑话，假口语，心照不宣的插话，只有同行才接得住的简写。
这一类更难防。端着听上去像装，读者当场就听出来；黑话听上去像熟练，读者往往听不出来，
而作者本人几乎永远发现不了，因为在他自己耳朵里那就是行话说得顺。判断标准是术语那两条，
有没有一个公认所指，有没有对应的普通词。过了是术语，留着；不过是黑话，换掉。

目标不是把话说浅。平实谨慎的原句不是毛病，那是目标，改到像聊天是另一种改坏。
要以童真的初心描写严肃的事情，并且乐于暴露自己的笨拙。

后面这半句不是姿态，它挡的是下面「它会朝哪个方向出错」记的那个失败。让句子变钝的那部分往往
就是限定条件，所以一次以可读性为目标的清理会持续朝着删掉它们使劲。写的人如果本来就偏爱变钝的
那一版，这条路径就窄了。边界是笨拙不等于邋遢，判据仍然是删掉它信息有没有少，以及读者问
"具体指什么"答不答得出一个事实。

十四类问题族逐条写在 [`references/taxonomy.md`](./references/taxonomy.md)，每一类都标注了来自哪个上游项目。

## 装与用

```bash
git clone https://github.com/shuxueshuxue/deslop ~/.claude/skills/deslop
```

放好之后在 Claude Code 里直接说「帮我去一下 AI 味」或者 `/deslop` 就会触发。
下面几条是不经过模型也能单独跑的：

```bash
python3 tools/measure.py FILE --scene academic      # 改之前先量
python3 tools/measure.py FILE --hits                # 词表候选
python3 tools/measure.py FILE --metaphor            # 借喻词与物理动词候选，带行号
python3 tools/measure.py FILE --comments            # 注释里的时态与在场者上下文候选
python3 tools/measure.py FILE --worksheet           # 逐句工作表，给审计用
python3 tools/measure.py --diff before.json after.json
python3 evals/run.py                                # 词表检测的回归分数
python3 tools/selfcheck.py                          # 把闸门跑在本仓库自己的文字上
```

## 流程

上图是完整流程，固定顺序，不许跳步。三件事值得单独说：

1. **动手之前先冻结。**把数字，引用，命令，报错，责任归属都划出来，另记一份关系清单，
   哪个数字修饰哪个对象，谁做了什么，什么基于什么。这层没有词表能替代。它错了以后大概也无法
   从成品倒推，因为成品里已经没有原来的关系了。
2. **只有第 06 步必须换一个空白上下文。**写的那个 agent 审不了自己写的东西，它重读的是自己的
   意图，不是纸面上的字。这条实现成一句硬要求，审计跑在一个空白上下文的子会话里。人在这条流程
   里出现两次，`bounded` scope 下的删除清单由人来定，以及最后收报告。
3. **回读分四遍，不许合并。**它们看见的东西不同。B 专门查刚写下的替换文字，
   D 专门查两处修改之间的交界，前三遍逐条走，看不见交界。

## 改到什么程度，由作者定

**场景决定语域目标。**七个场景各有各的锚点和默认动作，`chat`，`status`，`docs`，
`public-writing`，`academic`，`code-context`，`ui-copy`。学术稿和界面文案要的不是同一种"人话"。

**档位和 scope 是两个独立的轴。**档位是改多狠（`minimal` / `standard` / `aggressive`），
scope 是能不能删整句（`structural` / `bounded` / `in-place`）。混成一个轴，是改写要么不够要么
悄悄把文档缩掉三分之一的主要原因。`bounded` 下的删除清单交给作者定，不由工具决定长度。

**字数上限是第三种工具，由作者给。**编辑自己发明的上限，就是上面那个缩三分之一的问题换个名字。

**中文有三个语域锚点，各管一件事。**

| 锚点 | 它决定什么 |
|---|---|
| 日本电影的配音腔 | 句法。句子完不完整，主语在不在位，动词是不是双音节 |
| 百科条目 | 节奏与口气。有没有留悬念，分歧写没写成谁的分歧，把握程度标没标出来 |
| 新闻联播的播报体 | 对谁说，以及怎么停。面向所有人，不假设读者属于哪个圈子，事情说完就停 |

第三个带进来的毛病不比它给的少，意义拔高，口号，泛指的集体主语，程式化的正面收尾。
取的是前一半。英文那边的锚点是 Wikipedia，Hacker News 的技术评论，和好论文。

细则在 [`SKILL.md`](./SKILL.md)，它是这套流程的行为合同。

## 能数的和不能数的

一条指标只有在"命中基本都是真的"时才配进计数集。实测说不是，就降级，并且把理由印在每一份报告里，
防止有人悄悄装回去。

| 层 | 判定权力 | 内容 |
|---|---|---|
| **GATED** | 归零，或逐条具名 | 破折号 · 对偶反转 · 顿号 · 句中冒号 · 助手残留 · 知识截止免责 · 表情符号 · `-ing` 假分析 · 系动词回避 · 假区间 |
| **CAPPED** | 只有超出上限的部分算问题 | 路标词 · 自我评价 · 讲义腔 · 感叹号 · hedge 堆叠 · 句内加粗 · 内联标题项 · 尾部对比句 |
| **REPORTED** | 只打印，永不判定 | 句长变异系数 · 连词密度 · 名词化 · 借喻场 · 三件套候选 · 词表命中数 |

按实测降级的五条：

- **三件套列举。**毛病是真的，指标不是。扫的第一份文档上，5 处命中全是正常枚举。
- **连词密度。**95 条语料实测，判断标准反了。不该改的那组中位数 5.26/千字，高于该改的那组的 0.00。
  一对同密度用例把它钉死，叙事帖 80.00 该删一半，迁移文档 81.08 一个都不能删。
- **整句加粗。**修好计数器之后发现它抓不到真毛病，而整句加粗和加粗标签在形状上完全一样，要看意思才分得开。
- **尾部对比句**和**内联标题项。**这两条降在把闸门跑到本仓库自己文字上的那一次，命中分别是 6 比 1 和 11 比 0。

**有四类问题永远不进计数集，原因分两种。**一种是尺度不够，毛病只在整篇的尺度上存在，
没有单位可数，贯穿全文的比喻和过匀的节奏都是这样，只有整篇读一遍才看得见。
另一种是精确率不够，有单位，脚本也找得到，但命中不是基本都对，拟人和三件套是这样，
脚本仍然列候选并给行号，逐条由人判。

所以"脚本数不了"的读法是"只有人看得见"，不是"这条不重要"。

## 实跑读数

`worked-example/` 是在一份真实论文框架稿上做完的全流程，输入冻结在 `00-input.md`。

| 指标 | 前 | 后 |
|---|---|---|
| 破折号 | 38 | **0** |
| 对偶反转 | 7 | 1（豁免，已具名） |
| 自我评价 | 7 | 2（刻意保留） |
| 正文字数 | 3462 | 3385 |
| 句数 | 227 | 242 |

句子变多，字数变少。这是解压缩的特征，不是删减。38 个挂在破折号上的从句变成了句子，同位语，或者括号。

更值得看的是 `02-audit.md` 末尾那一节。第二遍和第四遍回读改掉了七条我自己的判断，
其中两条是矫枉过正（删掉一个带 hedge 的自评，等于把作者没下的论断改强了），
三条是拆句造成的交界损坏，逐行的两遍一处都没看见。

## 它会朝哪个方向出错

值得先说，因为它是这套流程自己造成的。

可读性是目标，而**让句子变钝的那部分恰好就是限定条件**。`clean-entry 容器`，`单次`，`smoke`，
`自主采纳`，这些词长得跟别的散文一模一样。就目前试过的几类特征而言，我们没有找到能让脚本认出
它们的形式标记，所以一次跑得好的语域清理很可能会优先削掉它们。

比一比：

> 在一个 clean-entry 容器里的一次 smoke 中，一个全新 session 自主采纳为零
>
> 一个 agent 通过了全部检查却没用那套工作流

第二句更好读，这份文档里的语域直觉基本都偏向它。从内容上看它同时是另一个论断，
而这条流程里后面的检查没有一处会报出这个差别。留下来的句子结构完好，归属正确，数字精确。

对策是顺序，不是更小心。**限定条件必须在语域处理开始之前就被冻结**，由知道数字来源的那个人
标一次，工具此后只负责别动。所以转述损耗跑在第 02 步而不是审计里，也所以它只标注不自动改。
它需要的信息不在文本里。

## 本仓库自查

`python3 tools/selfcheck.py` 把上面那张表里的闸门跑在 deslop 自己的文字上。15 个用本仓库口吻
写的文件，每一条命中要么改掉，要么在 [`references/selfcheck.tsv`](./references/selfcheck.tsv)
里留下名字和理由。没留名的命中判失败；命中已经没了理由还留着的也判失败，免得这张表慢慢变成
一张免死牌。

上面五条降级里的后两条就是这么来的。全仓破折号 0，这个是量出来的；比喻候选逐条判过，
自己引入的活比喻没有发现，这一条是人读出来的判断，不是计数。

`evals/run.py` 是词表检测的回归分数，61 条用例，召回 100%，两处已知误报都来自刻意放宽的规则
（文档里的 `你`，以及过度共情那条的 `请求`）。

## 来历

deslop 原来解决的是判断标准，压缩标点，burden of proof，前后指标，过校正回读。这一版把另外三个
项目并了进来。

| 项目 | 带进来的 |
|---|---|
| [说人话](https://github.com/MrGeDiao/shuorenhua) | 控制面：场景，保护片段，Tier，档位 × scope，无源引用三模式，两遍回读，annotation mode |
| [natural-talk](https://github.com/chengzhi-c/natural-talk) | 原则层 / 表达层的分层，数值上限，以及四家里最好的防矫枉过正清单 |
| [Humanizer-zh](https://github.com/op7418/Humanizer-zh) | 维基百科 *Signs of AI writing* 那套模式：意义拔高，`-ing` 假分析，系动词回避，同义词轮换，假区间，格式痕迹 |

四家在几处直接对立，每一处的裁决和理由写在 [`references/provenance.md`](./references/provenance.md)。
最要紧的两条：**注入灵魂**拆成了去味（默认开）和补声音（默认关，需要作者真有的材料）；
**连词密度**按实测废掉了全局阈值。

外面的抱怨帖是第五份材料，但不是第五个被合并的项目。它给的是别人注意到什么，不是一套规则。
能用的部分和每一条的出处在 [`references/field-reports.md`](./references/field-reports.md)。
进来的主要是代码注释和界面文案那一族，以及一条本仓库自己没做过的检查。被拒掉的是那条最流行的
路子，把文本交给另一个模型重写，理由和它的代价也写在那份文件里。

词表由 `tools/build_lexicon.py` 从四个上游 checkout 生成，不是手抄。去重按"能不能被已有正则命中"判，
不按字符串相等，否则同一个词会有四家四行。

顶部那条 banner 的底图由图像模型生成，提示词要求画面里不出现任何字母，字是后期用真字体排上去的。
图像模型排出来的字母是歪的，而在一个讲去 AI 味的仓库里，歪字母是最响的痕迹。底图画的是字行本身，
密而带花饰的左边渐变到干净的右边，属于比喻禁令唯一豁免的那种情况，所写对象本身就是那个域。
底图留在 `assets/banner-art.jpg`，合成脚本是 [`tools/make_banner.py`](./tools/make_banner.py)，
所以这张图可以重建。标语里不放会过期的数字。
